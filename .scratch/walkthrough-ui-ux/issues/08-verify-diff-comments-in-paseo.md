# 08: Verify diff comment handoff in Paseo

**What to build:** A maintainer can decide whether a reviewer can hand off a comment from a walkthrough hunk to the Paseo composer with its original diff context.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] Check the supported SDK surface for a composer handoff from an Explorer plugin panel.
- [x] On a live Paseo host, verify whether the handoff can carry the file, line, and diff source or record the missing capability and how it was verified.
- [ ] If supported, record the verified user flow and host requirements for a follow-up implementation ticket.

## Comments

- The installed `@getpaseo/plugin` 0.15.4 declarations expose composer pills and attachment-source registration. An Explorer panel on that SDK has no public API to find an agent's composer or edit its draft. Both the 0.16.0 and 0.16.2 published SDK declarations expose `useComposers` and `client.composers({ agentId })`. The selected agent's composer accepts `insertText(text)` and `focus()`. The tagged reference includes an Explorer-panel example. [Paseo 0.16.0 changelog](https://paseo.sh/changelog#0-16-0), [v0.16.2 client SDK](https://github.com/getpaseo/paseo/blob/v0.16.2/packages/plugin/src/client/index.ts#L86-L94), [v0.16.2 composer reference](https://github.com/getpaseo/paseo/blob/v0.16.2/public-docs/plugins/reference.md#reach-a-composer-by-reference)
- Paseo's built-in diff viewer keeps inline review comments in a workspace review draft and turns them into a native review attachment. The public v0.16.2 composer API can add items from the calling plugin's own attachment sources. It exposes no operation to create or attach a built-in review comment. A walkthrough handoff can carry the comment and its context as editable draft text. A native review attachment would require a public API for the built-in review draft. [Built-in inline review implementation](https://github.com/getpaseo/paseo/pull/530), [v0.16.2 composer API](https://github.com/getpaseo/paseo/blob/v0.16.2/public-docs/plugins/reference.md#composer-items)
- The isolated host returned version `0.16.2` from `GET /api/status`. Its served web client exposed `useComposers` and the `composers` capability, and a temporary agent-scoped Explorer probe plugin loaded. The probe would insert an unsent draft with `src/example.ts`, line `42` on the new side, and `staged Git diff`. The fixture had no available provider models and refused agent creation with `Provider 'codex' is not available`. This prevented exercising draft insertion or focus. The live check covered the host and API availability.
- The API requires the 0.16 series or newer on the client. A plugin adopting it unconditionally needs a matching SDK and manifest minimum for both the app and daemon. The proposed follow-up flow is to let the reviewer choose an existing agent in the same workspace and insert a hunk comment with the repository-relative path, old or new side and line or range, and diff source such as staged, unstaged, or a commit comparison with its refs. Focus the composer so the reviewer can edit and send the draft themselves. The public reference API cannot address a new-agent draft, so the action needs an unavailable state when the workspace has no existing agent. Verify that flow on a 0.16 host with an available agent before shipping it. [Composer targeting and focus](https://github.com/getpaseo/paseo/blob/v0.16.2/public-docs/plugins/reference.md#reach-a-composer-by-reference), [Plugin version requirements](https://github.com/getpaseo/paseo/blob/v0.16.2/public-docs/plugins/reference.md#requirements)
